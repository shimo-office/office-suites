## 从这些话开始

| 你要做的事 | 可以直接发送 | 你应得到什么 |
|---|---|---|
| 找文件 | “找到报价政策，列出名称和链接，重名时先让我选。” | 可访问的真实文件列表 |
| 读文档 | “总结这份文档的重点和待办事项，附原文链接。” | 基于正文的总结；读取不全时说明范围 |
| 下载交付 | “把这份文件下载到当前工作目录。” | 本地文件及保存位置 |
| 导入方案 | “把方案.md 导成石墨文档，放到这个文件夹。” | 新在线文档的链接及内容核对结果 |
| 整理表格 | “把工作表1的 A1:C1 设为蓝底白字，完成后核对。” | 指定范围的修改及实际核对结果 |
| 新建周报 | “在这个文件夹新建一份本周周报文稿。” | 新文稿的名称、位置与链接 |

把“这份文档”“这个文件夹”替换为实际链接，或在对话中附上链接和本地文件。编辑时补充工作表、单元格范围或具体段落；同名目标不清楚时，Agent 会先让你选择。

下面是各场景的详细支持范围。你只需参考“场景与话术”；命令和验收细节供 Agent 执行时查阅。“API”表示直接调用服务；“页面操作”需要可用的浏览器；“人工禁用”需由你在网页完成。

## 安全边界

文件锁定、限制编辑、高级权限、成员级授权、彻底删除必须由有权限的用户在石墨网页人工操作。收回和其他权限变更也不由 CLI 执行；导入只处理文件，后续权限意图先确认再交人工设置。`delete` 直接移入回收站，不弹确认；恢复用 `restore`。详细规则见 [安全策略](../SECURITY.md)。

## 文件与目录

| # | 场景与话术 | 执行方式和命令 | 行为与验收要点 |
|---:|---|---|---|
| 1 | 搜索：「找一下报价政策。」 | API：`search <关键词> [--limit N]` | 返回实际匹配文件及链接；重名时按路径选择，不编造正文命中。 |
| 2 | 空间与目录：「我在哪些空间？这个文件夹有什么？」 | API：`spaces`、`ls <链接或@别名>` | 核对目标与数量；受 limit 限制时说明截断。 |
| 3 | 文件出处：「这份文件在哪个空间？」 | API：`info <链接>` | 返回文件类型、权限及可访问的路径；无权限如实说明。 |
| 4 | 导入交付：「把方案.md 导到项目文件夹。」 | API：`import <文件> --to <位置>`；权限：人工禁用 | 转换为在线文件后核对链接、类型和正文；权限变更交用户网页处理。 |
| 5 | 文件夹归档：「把这个项目文件夹拉下来。」 | API：`pull <目录> [--out 路径] [--since 7d] [--limit N]` | 只下载当前层；子目录在 manifest 记为跳过，不递归。逐项列失败，有失败项非 0 退出。 |
| 6 | 新建：「建一份周报文稿，再建个归档文件夹。」 | API：`new <名称> --type <类型> [--to 位置]`；`mkdir <名称> [--to 父文件夹]` | `new` 建文件，`mkdir` 建文件夹；`doc` 是轻文档，`docx` 是文稿。公开类型完整为 `doc/docx/sheet/slide/table/form/mindmap/flowchart`，具体含义见命令参考；核对实际类型及所在位置。 |
| 7 | 改名：「把这份草稿改名为方案 v2。」 | API：`rename <链接> <新名字>` | 核对名字及 GUID 不变；批量时逐项记录失败。 |
| 8 | 回收与恢复：「把自检文件移到回收站，再恢复。」 | API：`delete`、`trash`、`restore`；彻底删除：人工禁用 | 删除只进回收站，恢复后核对原 GUID 和位置；不提供自动彻底删除。 |
| 9 | 权限巡检：「找出这个空间的公开链接。」 | API：`audit <目录> [--limit N]` | 只读取权限，未知值/读取失败独立分组；未知或截断时非 0 退出，不算私有。 |
| 10 | 权限调整：「把这些文件改成企业内可读。」 | 人工禁用：CLI 拒绝权限写入 | 可先 `audit`，再打开网页由用户逐项确认；不得代改成员授权或分享权限。 |
| 11 | 读正文：「读这份文稿，给三条要点。」 | API：`read <链接> [--max-chars N]` | 从实际导出正文总结并附原文链接；截断、扫描件或解析失败明确指出。 |
| 12 | 周报：「汇总本周更新的项目文档。」 | API：`ls <目录> --since 7d`，逐份 `read` | 基于实际更新和正文汇总，区分已验证内容与推断，不用文件标题替代正文。 |
| 13 | 下载附件：「下载这份原始附件。」 | API：`get <链接> [--out 目录]` | 附件原样下载；在线文件按类型导出。核对本地文件存在和可读。 |
| 14 | 上传：「把报告.pdf 传到项目目录。」 | API：`upload <文件> --to <位置>` | 原样云文件；未指定位置时先给可选目标，再提交，不能默认猜位置。 |
| 15 | 常用位置：「以后 @project 就是这个文件夹。」 | API / 本地配置：`fav add/list/show/rm` | 本地仅保存别名与链接；用 `ls @project` 验证指向，不保存凭据。 |

## 编辑与协作

以下 `editor` 动作的 payload、读回和截图要求统一见 [命令参考](cli-reference.md#编辑器接口与页面入口)。页面操作采用下文唯一浏览器顺序。

| # | 场景与话术 | 执行方式和入口 | 行为与验收要点 |
|---:|---|---|---|
| 16 | 与我相关：「谁 @ 了我？我订阅了哪些更新？」 | API：`editor --action mentions-list/comments-list`、`subscriptions`；定位：页面操作 | 列出真实数据后由用户选择文件；没有全量“最近正文”接口时不猜。 |
| 17 | 留痕与版本：「打开历史，保存交付前版本。」 | 页面操作：`history-show/history-hide` 展示历史；持久页面保存版本 | 历史展示需要 `--verify`，只证明面板展示；CLI 拒绝 save-version 临时面板工作流。单元格历史先明确工作表、行列。 |
| 18 | 字符与段落：「查找旧标题并替换，调整正文格式。」 | 页面操作：菜单与选区 | 通用 `find/replace-all` 没有已暴露的 SDK 方法，CLI 返回页面提示；不能把它们当稳定 API。文稿固定动作另见扩展编辑文档。 |
| 19 | 文内表格与图片：「插入表格，调整图片环绕。」 | 页面操作：目标套件的菜单、对象与选区 | 逐对象核对结构和位置；轻文档与文稿的能力不互相外推。 |
| 20 | 评论与提及：「读取评论，并给指定段落添加评论。」 | API：`comments-list`；页面操作：`comment-add`、提及和定位 | CLI 拒绝 comment-add；须在持久页面提交，通知收件人须符合用户授权，并核对实际结果。 |
| 21 | 预览与打印：「预览这份文档并导出打印文件。」 | 页面操作：持久页面预览/打印菜单 | CLI 拒绝临时 print 面板；要求文件时必须检查实际 PDF。 |
| 22 | 文档重排：「调整标题层级和页面宽度。」 | 页面操作：样式、正文选区与页面设置 | 通用 `page-width` 未暴露 SDK；以页面与导出内容证明结果。 |
| 23 | 表格写入：「写入本周数据，追加一批，再插入或删除指定行。」 | API：`sheet-update/sheet-append/sheet-insert/sheet-delete` | 插删行是 API；插删列和工作表改名/隐藏是页面操作。读回之外还需导出核对及截图，空行不能只靠 values 判断。 |
| 24 | 表格整理：「冻结首行，按金额筛选，并将表头设为蓝底。」 | API：`sheet-format` 的 `attrs.background`；页面操作：冻结、排序、筛选、条件格式、视图 | 底色走 API，不改走菜单；冻结/排序/筛选的通用 CLI 动作明确拒绝未暴露 SDK。 |
| 25 | 表格清洗：「去重、分列并检查文件大小。」 | 页面操作：数据工具与文件工具 | 对照处理前后范围及保留记录；没有稳定接口时不声称 API 已完成。 |
| 26 | 表格计算与分析：「核对公式，生成透视表。」 | 页面操作：公式、名称、透视表及分析菜单 | 读回公式与结果，检查引用和筛选范围；不把示意数据当真实结果。 |
| 27 | 校验与格式：「设置输入规则，调整底色并合并表头。」 | API：`sheet-format`、`sheet-merge`；页面操作：数据验证、行高列宽 | 格式 API 仅接受已验证属性，详见命令参考；数据验证没有已暴露 SDK。按具体子动作分别验收。 |
| 28 | 表格输出：「下载这张表并打印。」 | API：`get` 导出 XLSX；页面操作：打印 | `get --format csv` 明确不支持；默认 XLSX 导出失败可回退 PDF，须看 exportType，不假装仍为 XLSX。打印文件须实际生成并可读。 |

## 浏览器优先级

这是全库唯一维护的浏览器选择规则；教程和技能只引用本节。

1. 先检查当前宿主实际可调用的内置浏览器，有则优先使用。WorkBuddy 的 `present_files`、Codex 桌面的浏览器等依当前工具可用性判断，不按产品名字永久假定“有”或“没有”。
2. 没有可用内置浏览器时，先说明会启用独立浏览器，取得用户同意后使用 `agent-browser`；未安装或不可用时不要假称已启用。
3. 以上不可用时，说明将打开本机外部浏览器并取得用户同意，再使用 `shimo-net open <链接>`，使用独立 open-profile，不注入 CLI 会话、不留远程调试端口；需登录时由用户完成，再由可用页面工具操作。
4. 最后才在用户同意打开本机默认浏览器后使用 `shimo-net open <链接> --default`。它选择默认浏览器应用；支持的 Chromium 应用仍使用 CLI 隔离配置，其余交系统打开，不能承诺已有登录态。

以上授权要求也覆盖会启动本机浏览器的 `login`、会话复用、`subscriptions --open`、`editor --verify`、`mentions-list/comments-list` 及三期页面动作；只读接口也可能需要浏览器。用户拒绝时使用纯 API 可完成的部分，并报告需页面核验的部分未完成，不换工具绕过拒绝；可用 `--no-browser` 或 `SHIMO_NET_NO_BROWSER=1` 禁止相关启动。用户已明确允许本次浏览器方案时，无需重复询问。页面仍为登录页、空白页或编辑器未就绪时不能计为验收成功；允许有界等待与只读重试，禁止因此盲目重放已受理的写入。人工禁用项不因浏览器可用而变为 Agent 可代办项。

## 登录与会话

先检查 `whoami --json`、`session status --json`。普通登录可能复用 Chrome / Chromium / Edge / Brave / Vivaldi 的原账号；换账号必须 `login --new`，完成后再查 `whoami`。完整流程和 401 FAQ 只在 [安装说明](install.md#登录复用会话与切账号) 维护。

## 自然语言示例

完整任务可按“文件链接 + 目标位置或范围 + 期望结果”描述。例如：“把这张销售表的工作表1 A1:C1 设为蓝底白字，再导出和截图核对。”其他话术见[开头的任务示例](#从这些话开始)。
