# 三期功能实施标准与批次

> 依据：`石墨办公套件私有部署CLI功能清单-V1.pdf`（三期 2026.11.24，29 项）
> 原则：**真实现、可复核、不假成功**。没有导出物证/读回/截图的动作，不返回 `ok:true`。

## 一、硬标准

每个三期动作必须过三层门：

1. **命令层**：退出码、`ok`、明确的 `method`；
2. **数据层**：读回接口（如 `sheet-values`、导出文件解压后的 XML）；
3. **物证层**：导出的 docx/xlsx/pptx 文件或页面截图。

任一层缺失，判定为“未实现”，不得写“可用”。页面动作没有 `--verify` 或宿主内置浏览器时直接失败。

## 二、现状探测结论

| 编辑器 | 实际可用的程序入口 | 结论 |
|---|---|---|
| 文档（document） | `window.smsdk.__DRIVE_SDK__.editor.doc` 仅 `insertMarkdown`/`changeTitle`/目录/选区；`editor.actions` 可开历史、评论、打印面板 | 富文本字符/段落格式**没有稳定 API** |
| 文稿（documentPro） | 同上；页面是 canvas 编辑器，DOM 里没有 contenteditable | 格式必须走工具栏 UI 自动化或官方新 API |
| 表格（spreadsheet） | 同源 `/lizard-api` 的 values/attrs/mergeCells/rows；格式仅 background/color/bold/italic/underline 确认落地 | 高级整理/公式/透视/校验仍无 API |
| 幻灯片（presentation） | 需单独探测；预计以 UI 自动化或 pptx 导入导出为主 | 待逆向 |
| 应用表格 / 表单 | 需探测 REST/内部接口 | 待逆向 |

因此三期不能沿用二期“找到一个 SDK 方法就返回成功”的做法；每一项必须先确定入口，再写验证。

## 三、批次

### 批次 A：文稿排版（29–32，9 项）

- 字符格式、段落格式、主题字体/页面颜色
- 文内表格结构/样式
- 图形布局/样式
- 页面设置与查找替换、@ 提及

技术路线：canvas 编辑器 + 工具栏 UI 自动化；导出 `.docx` 后解压 `word/document.xml`、`word/styles.xml`，检查 `<w:b/>`、`<w:sz>`、`<w:jc>`、表格/图片节点，再用截图复核。

### 批次 B：幻灯片（33–36，10 项）

- 批量换主题/版式、页面增删复制隐藏
- 文本格式、占位符
- 图形/表格/音视频
- 批量动画、查找替换/演示设置、打印

技术路线：优先探测 pptx 导出/导入与页面 API；导出 `.pptx` 后检查 `ppt/slides/*.xml`、`ppt/theme`、`ppt/media`。

### 批次 C：应用表格 / 表单（37–42，10 项）

- 数据表/字段、记录批量操作
- 视图、仪表盘/图表
- 表单题目/逻辑、设置/发布、结果统计

技术路线：优先 REST/内部接口；无接口时页面操作，导出结果或读回结构作为物证。

### 批次 D：二期遗留

- 表格冻结/排序/筛选/条件格式/数据验证/公式/透视
- 文稿/幻灯片页面动作的宿主浏览器会话前提
- 搜索无命中提示、`sheet-merge` range 统一

## 四、批次 A 技术预研结论（2026-11-18）

- 成功样本：CDP 点击画布 + `Input.insertText` 写入 7 个字，`Cmd+A`/`Cmd+B`/`Cmd+I`/`Cmd+U` 后导出 `.docx`，`word/document.xml` 出现 `<w:b/>`、`<w:i/>`、`<w:u/>`，证明“UI 自动化 + 导出 XML”这条路可行。
- 失败样本：同一命令在 Chrome 没有前台焦点、页面尚未完全可交互时，字数为 0；截图空白，导出的 docx 没有文本。连续重试、`Page.bringToFront`、focus emulation、激活 Chrome 都不能稳定解决。
- 结论：**不把当前 CDP 半成品合入 CLI**。批次 A 需要以下之一后才能按“真实现”交付：
  1. 官方文稿格式 API；
  2. 明确允许前台 Chrome 的 UI 自动化（需要可访问性/窗口焦点，且要接受较慢、依赖页面版本）；
  3. 改用导出 docx → 修改 XML → 导入新文件的“生成新文稿”模式（不是原地编辑，需产品确认）。

## 五、交付顺序

1. 先做批次 A 的“字符格式”最小闭环：写入一段文本 → 选中 → 改字体/字号/颜色 → 导出 docx 验证 XML → 截图。
2. 同一套 CDP 工具栏自动化复用到段落格式、文内表格、图形。
3. 再做批次 B、C；每批单独发版，不一次性宣称 29 项完成。

## 六、验收口径

- 文稿：导出 docx，检查 `word/document.xml`/`styles.xml` 的实际节点，不只信页面提示。
- 表格：导出 xlsx，检查 `xl/worksheets/sheet1.xml` 与 `xl/styles.xml`；`applied` 不作为证据。
- 幻灯片：导出 pptx，检查 slides/theme/media XML。
- 表单/应用表格：读回结构 + 导出/截图。
- 任何一项没有物证，状态只能是“未实现”或“页面待人工”，不能写“可用”。
