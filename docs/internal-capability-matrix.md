# 内部能力确认矩阵

本表汇总当前 Go CLI `0.9.1` 已支持的 28 个场景和 45 项能力。表中的“API”指已在石墨编辑器 API 文档中确认的页面 `sdk` 方法；当前仓库还没有把这些方法全部封装成高层命令。

已核对的后端接口：[获取文件内容中所有的 @ 人信息列表](https://support.shimo.net/apidoc/docs-site/6000018/api-3470923)、[获取文档中的评论列表](https://support.shimo.net/apidoc/docs-site/6000018/co1.8.20260630/api-3470916)。

## 结论

- 基础文件管理、权限、读写和下载能力已经由 REST `/api/v1` 命令覆盖，见 [cli/README.md](../cli/README.md) 和 `shimo-net schema`。
- 当前真实回归确认：`phase2` 的同源 API 读取可用；页面 SDK 动作在当前页面未暴露 `globalThis.sdk`，统一转网页 computer-use。`phase2` 是现有兼容命令名。
- 没有已确认 API 的项目使用默认浏览器兜底：`shimo-net open <链接> --default`。Agent 按 `shimo.net/desktop` 的可访问性树或 DOM 完成操作，再返回截图路径。
- SDK 只在编辑器页面和支持的桌面版本中可用。页面没有暴露 SDK、方法不存在或运行时抛错时，CLI 会返回浏览器兜底提示，不会伪造成功。

## 已验证 API 调用约定

```bash
# 读取 @人列表
shimo-net phase2 <链接> --action mentions-list --json

# 读取评论列表
shimo-net phase2 <链接> --action comments-list --json
```

入口会启动 CLI 自己的隔离 Chrome 配置，读取 `SHIMO_NET_COOKIE`、macOS Keychain 或凭据文件中的会话并通过 CDP 设置 cookie，刷新页面后执行同源 API。cookie/sid 永远不出现在 stdout、stderr、JSON 或截图文件名中。成功后默认写入 `~/.shimo-net-cli/screenshots/`，也可以用 `--screenshot` 指定路径。

订阅文件列表：

```bash
shimo-net subscriptions --json
shimo-net subscriptions --open 1 --default
```

该命令扫描桌面、空间及指定深度的文件夹，逐文件调用订阅状态接口并按最近更新时间排序。服务端没有返回“最近更新正文”的用户接口，所以用户选中文件后必须打开对应文档查看。

## 浏览器兜底协议

1. 先执行 `shimo-net whoami --json`；401 或未登录时执行 `shimo-net login`，成功后重试原命令。
2. 能通过 CDP 控制的隔离浏览器会读取 Keychain 并注入 cookie；`shimo-net open <链接> --default` 连接的是操作系统已运行的默认浏览器，没有远程调试端口，不能安全地把 cookie 注入任意浏览器进程。此时使用浏览器自己的登录态；若没有登录态，让用户在该浏览器登录一次，或改用编辑器入口。
3. 按已实测的套件入口操作：轻文档顶部有“正文、字体、字号、插入、评论”；表格菜单有“冻结、排序、筛选、条件格式、数据验证、版本管理、评论”；幻灯片菜单有“编辑、插入、格式、动画、排列、设计、幻灯片、视图、演示、审阅、工具”。同时以当前页面可访问性名称为准，不依赖猜测的 CSS 选择器。
4. 写操作（编辑、评论、权限、删除、打印）先向用户确认目标、范围和影响，再执行；完成后保存页面截图并返回绝对路径。
5. 页面无权限、API 未开放或控件名称随版本变化时如实报告，并保留失败截图/页面地址，不能声称操作成功。
