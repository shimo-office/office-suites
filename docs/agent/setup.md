# Agent 自动安装执行说明

本页由 Agent 读取并执行。用户入口见[一句话开始使用](README.md)。用户已请求安装时，CLI、技能接入、路径修复和验证都由 Agent 完成，不把命令或文件复制步骤交还给用户。

## 1. 检查当前环境

- 先检查当前会话的内置预览和实际浏览器操作工具，按[浏览器规则](../scenarios.md#浏览器优先级)区分展示与操作。内置预览只能展示时，可用外部 Computer Use 完成页面操作；不要先运行 CLI 来替代预览。随后确认当前助手、操作系统、CPU 架构、工作目录及实际可用的本机工具。云端会话不能直接使用用户电脑上的程序和登录态。
- 检查已安装的 `shimo-net` 和宿主已加载的 `shimo-net-cli` 技能；查看真实版本与来源，已有可用安装就复用。不要覆盖用户修改过的技能，也不要另装同名副本。
- 已有可运行 CLI 时，用 `shimo-net config show --json` 检查服务地址；尚未安装时先记录用户提供的地址，安装后再配置。用户指定客户域名时按该地址配置；已有地址不擅自改回公有云。全新安装且未指定域名时使用 `https://shimo.net`。
- 缺少工具或被权限限制时说明具体原因并请求所需的最小授权，不要求用户关闭全部沙箱。若宿主无法执行本机命令，说明需要切换到本地任务；不得报告安装成功。

## 2. 安装或复用 CLI

由 Agent 根据[安装说明](../install.md)选择适合当前系统的方式，并执行所有命令：

| 当前环境 | Agent 的操作 |
|---|---|
| 已有可用 CLI | 核对版本和实际执行路径后继续，不重复安装 |
| 有受支持的 Node.js / npm | 从官方 npm registry 安装 `shimo-net-cli`，使用命令 `shimo-net` |
| 无 Node.js | 从本仓库正式 Release 下载对应系统和架构的原生程序；不要在未选择 CLI 浏览器登录方案时运行含登录流程的 bootstrap 脚本 |
| 已安装平台技能包 | 按包内[运行说明](runtime.md)复用匹配版本 CLI，或启用包内运行器 |

处理好当前会话的命令路径；需要持久配置时保留原文件内容、避免重复添加。不得为安装而覆盖用户项目的依赖或配置。安装失败时保留错误，有限重试或换用官方支持的安装渠道，不能把超时当成功。

npm 和原生程序安装不会替你完成登录。`bootstrap.sh` 会主动执行 `whoami` 并可能启动 `login`，因此仅在 CLI 浏览器登录方案已选定并获准后使用；内置页面任务或仅需安装程序时选 npm、原生二进制或纯安装器。

`bootstrap.sh` 也不等于完整的宿主接入：它只给 Codex/DSH 写入脚本预设目录，不给 WorkBuddy/豆包安装技能；默认 latest 会重新下载 CLI。运行脚本后仍须完成下一节，检查当前宿主是否真的识别技能。

## 3. 由 Agent 接入技能

先检查宿主已经发现的技能及其版本。缺失时，获取与 CLI 对应的正式 Release 的 `SKILL.md`；例如 CLI 为 `0.9.21`，来源为：

```text
https://github.com/shimo-office/office-suites/releases/download/v0.9.21/SKILL.md
```

版本号须替换为实际版本，不固定使用示例版本。文件先下载到临时位置，确认不是 HTML 错误页、元数据 `name` 为 `shimo-net-cli` 且 `version` 匹配，再安装到当前宿主支持的位置。平台 ZIP 还包含运行器和引用文档，应按包内结构安装，不能只取其中的 SKILL.md 后丢弃依赖。对已有平台技能包遵循其版本要求，不混用其他版本的运行器。

| 当前助手 | Agent 接入方式 |
|---|---|
| WorkBuddy | 优先复用已安装并启用的技能。缺失时，使用当前客户端提供的技能安装工具；在支持项目配置的本地工作目录，可由 Agent 写入 `.codebuddy/skills/shimo-net-cli/SKILL.md`。这份技能只对该项目生效；不要把项目安装说成所有任务都可用。跨项目接入使用当前客户端支持的用户级技能机制，不猜测私有目录。 |
| Codex | 优先使用当前会话提供的技能安装工具。手动写入由 Agent 执行：当前官方用户目录是 `~/.agents/skills/shimo-net-cli/SKILL.md`，项目目录是 `.agents/skills/shimo-net-cli/SKILL.md`。旧客户端或自定义配置以实际已发现目录为准；不要在旧目录和新目录各装一份。 |
| DeepSeek Harness | 由 Agent 放入当前 DSH 技能目录，默认 `~/.dsh/skills/shimo-net-cli/SKILL.md`；有自定义目录时以实际配置为准。 |
| 豆包工作 | 在“本地电脑”任务中，由 Agent 获取并读取同版本技能说明，按其约定调用本机 CLI；本流程不假定有独立技能目录，也不声称已跨会话永久安装。新任务中未保留时由 Agent 重新读取。 |

WorkBuddy 的[官方项目配置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)说明了 `.codebuddy/skills/`；[官方技能说明](https://www.workbuddy.ai/docs/zh/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills)介绍了导入与安全检测。Codex 的目录与加载规则见[官方技能文档](https://developers.openai.com/codex/skills)。宿主版本不支持上述方式时，根据当前工具与官方说明处理，不臆造安装 API。

优先让 Agent 完成安装和加载检查。只有平台要求本人确认授权或安全检测时，才提示用户完成该确认，不绕过检测。只有确认当前会话无法刷新技能，才提示新建会话；重开后继续验证。仅文件存在不能证明宿主已加载：需在技能列表中发现、实际读取技能，或由宿主工具确认。报告要区分“已被宿主识别”和“当前任务已读取说明”。

## 4. 配置服务与登录

先用 `shimo-net version --json` 检查程序。尚未选择 CLI 浏览器方案时，诊断与 API 账号检查一律加 `--no-browser`：`shimo-net doctor --no-browser --json`、`shimo-net session status --no-browser --json`、`shimo-net whoami --no-browser --json`。普通诊断可能触发本机浏览器会话收取，不能先执行再判断浏览器选择。

内置浏览器登录与 CLI 凭据独立。页面已可用而 API 未登录时，如实说明两条通道状态；纯页面任务可继续，不为它强制启动外部 Chrome。确需配置 CLI 会话时，说明外部登录要求并按既有授权处理，不能声称内置登录已同步到 CLI。根据真实结果处理：

- 服务地址未初始化时执行 `init --origin <服务地址>`；客户私有域名不替换成默认地址。
- CLI 账号已可用就继续。确需 CLI 登录且其浏览器方案已获准时，遵循[登录与会话](../install.md#登录复用会话与切账号)和[浏览器规则](../scenarios.md#浏览器优先级)，由 Agent 发起登录，由用户在网页输入凭据。
- 已存会话过期或域名不匹配时不能静默换成另一账号；用户要求切换账号时用 `login --new`，完成后重新验证。
- `doctor` 的未登录错误不等于程序未安装。区分网络、路径、权限、登录和浏览器错误，按具体原因处理。

浏览器使用遵循现有授权，不重复索要已经获得的许可，也不把安装请求当成读取或改写业务文件的授权。不要向用户索取密码、cookie、验证码或 token。

## 5. 验证并交付

分别核对程序版本、技能接入方式/生效范围和账号连通性。任何一项未完成都说明具体状态，不能用文件下载成功、目录存在或历史截图代替本次结果。

全部完成后，用简短说明告知“可以开始用自然语言操作石墨”，并提示技能生效范围。不要输出账号明细、凭据或大段终端日志。下一步直接执行用户的自然语言任务；没有指定任务时，可以建议“找到季度报告，总结重点并附链接”。

开始业务操作前读取 `shimo-net schema --json` 和已接入的技能。所有写入须按技能要求核对结果；权限变更等人工操作边界不因自动安装而改变。
